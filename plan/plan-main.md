## 6. Личный кабинет зрителя — план

| **Мои билеты** | Вкладки «Будущие» / «Прошедшие» / «Возвращённые»; карточка билета: спектакль, дата, время, площадка, место или категория, QR, статус | T-051 |
| **Билет крупно** | QR на весь экран для предъявления, «Добавить в календарь», адрес площадки | T-051 |
| **Заказ** | Состав, сумма, оплачено бонусами, ссылка на чек, статус возврата | T-051 |
| **Возврат** | «Вернуть», если разрешено правилами и сроком; причина; статус «в обработке» / «возвращено» | T-052 |

| **Пригласить друга** | Персональная ссылка, простое объяснение правил, сколько друзей уже купили | T-062 |
| **Профиль** | Имя, телефон (по желанию), задать / сменить пароль, привязать / отвязать Яндекс ID, выйти, выйти на всех устройствах | T-055, T-056 |

### 6.2. Порядок работ

1. 🟡 **Сессии и вход по коду (T-050)** — сделано 21.10.2026, осталось: проверка на PostgreSQL, почтовый провайдер. `POST /api/auth/email-code/request` и `/verify`: код хранится только хешем, одноразовый, с TTL, лимитом попыток и отправки; одинаковый ответ для существующей и несуществующей почты. Cookie `HttpOnly; Secure; SameSite`, отзыв при выходе. Подключить готовые формы `/login`, `/register`.
2. 🟡 **Пароль (T-055, по решению заказчика)** — вход по паролю и пароль при регистрации сделаны (scrypt); осталось задание/смена в профиле. Хеш argon2id, лимит попыток, задание пароля при регистрации и в профиле, восстановление — через вход по коду. Оценку объёма согласовать.
3. **Вход и регистрация через Яндекс ID (T-056, по решению заказчика).** Кнопка «Войти с Яндекс ID» на `/login` и `/register` над формой. OAuth 2.0 (Authorization Code + PKCE) через `oauth.yandex.ru`, данные — `login.yandex.ru/info` (почта, имя). Приложение регистрирует театр на своём аккаунте в Яндекс OAuth; `client_secret` — только на сервере. Защита: `state` против CSRF, проверка redirect URI. Связка аккаунтов — по подтверждённой почте Яндекса: если покупатель с такой почтой уже есть, вход в него, иначе новый аккаунт; согласие на обработку ПД — на нашей стороне при первом входе. Отвязка Яндекса и выход — в профиле. Тесты: подделанный `state`, отказ пользователя на экране Яндекса, почта без подтверждения. Нужен сервер (на GitHub Pages не работает).
4. **Маршрутизация кабинета.** `/account` без сессии → `/login`; после входа — назад, откуда пришёл. Меню «Личный кабинет» уже переключается по сессии (`useSession` в `components/auth/session.ts`) — заменить демо-источник на ответ сервера, ссылку в подвале (`ACCOUNT_HREF`) — по сессии.
5. **Мои билеты и заказ (T-051).** Только собственные данные (проверка customer ID на сервере), статусы — с сервера, не из браузера.
6. **Возврат (T-052).** Проверка правил, защита от двойного возврата, статус «в обработке» до ответа банка.
7. **Бонусы и рефералы (T-060…T-064)** — после подтверждения правил (T-003).
8. **Профиль** — после шагов 1–3: имя, телефон, пароль, привязка/отвязка Яндекс ID, выход.

### 6.3. Готово, когда
- Истёкший, повторный и подобранный код отвергается; по форме нельзя узнать, есть ли такая почта.
- Вход через Яндекс ID с подделанным `state` или чужим redirect URI отклоняется; повторный вход той же почтой попадает в тот же аккаунт.
- Зритель видит только свои заказы и билеты (тест на чужой ID).
- Повторное нажатие «Вернуть» не создаёт второй возврат денег.
- Кабинет работает с клавиатуры и экранным диктором, на телефоне шириной 360 px.

4. **Новые коллекции (T-025, T-026 и др.)** — люди / труппа, архив, новости, отзывы, партнёры, настройки сайта; перевод страниц «О театре», «Труппа», «Руководство», «Репертуар», «Контакты».
5. **T-022, T-024** — страницы, документы, перенос с Tilda, карта редиректов.
6. После продаж: заказы, билеты, возвраты, платёжные события, чеки, письма.
7. После правил лояльности: настройки бонусов и корректировки.
8. **T-065** — канбан корпоративов.
9. **T-074** — обучение театра: контент, афиша, цены, возвраты, заявки, типовые инциденты.

### 7.4. Готово, когда
- Кассир не может изменить цену, роль или настройку — проверено тестом API.
- Каждое действие с заказом и возвратом записано с сотрудником, датой, причиной и результатом.
- Секреты платёжной интеграции не видны и не редактируются в админке.
- Редактор меняет спектакль, человека или новость — изменение видно на сайте без участия разработчика.

## 11. Риски

- **Срок банка** не зависит от разработки: без T-001 продажи и кабинет не запустятся.
- **Расширение объёма** (места в зале, вход по паролю и через Яндекс ID, новые разделы «О театре») увеличивает исходную оценку 205 часов — согласовать до обещания сроков.
- **Контент:** без фото и биографий страницы людей остаются с инициалами и заглушками.
- **Ticketscloud** работает до полной приёмки новых продаж — его отключение всегда последний шаг.
