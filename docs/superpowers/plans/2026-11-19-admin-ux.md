# План: путь администратора «выставить спектакль в продажу»

Дата: 19.11.2026. Ветка: `feat/admin-ux` (от `f3373d7`). Рабочая копия: `/Users/thesimakov/Documents/GitHub/trds-admin-ux`.

## Spec (источник требований)

UX-аудит живой админки 19.11.2026 (проход в браузере + разбор кода). Главные выводы:
- Окна подтверждения/ввода (`useAdminDialog`, `src/payload/components/AdminDialog.tsx`) рендерят `<form>` внутри формы документа Payload → кнопка окна отправляет форму показа: перезагрузка, потеря данных; «Применить шаблон» и «Сохранить как шаблон» на показе не работают.
- Поле «Начало» показа: ручной ввод «15.03.2027 19:00» молча превращается в 1 янв. 2026; формат 12 ч «ДП/ПП».
- Вкладка «Показы» в спектакле (join) не показывает черновые показы; две дублирующие кнопки создания.
- Удаление показа со схемой зала всегда запрещено (`guardPerformanceDelete`, `src/payload/hooks/inventorySync.ts`), даже без продаж; админка показывает «An unknown error occurred». После удаления показа остаются строки `commerce_seats` / категории inventory.
- Спектакль с показами удаляется без проверки — показы остаются без спектакля.
- Показ называется техническим ключом (`useAsTitle: 'code'`), его не отличить в списках и при выборе.
- Цены категорий билетов вводятся в копейках («1 000 ₽ = 100000»), в схеме зала — в рублях.
- Категории билетов — отдельный раздел «Продажи», показ выбирается из плоского списка ключей; не объяснено, нужны ли они при продаже по схеме.
- Нет проверки готовности: показ публикуется без цен / с неопубликованным спектаклем или площадкой и молча оказывается без продажи; пустое «Продажи с» открывает продажу сразу при публикации.
- Схема зала: «Закрыто 65» без объяснения и способа быстро открыть; отметка «Цены не утверждены» под картой.
- Меню: разделы разбросаны («Афиша», «Продажи»); подписи «Создать новый Спектакли»; обязательный «Анонс» спрятан на второй вкладке спектакля.

## Tasks

### Task 1: Окна подтверждения не отправляют форму документа

**Files:** `src/payload/components/AdminDialog.tsx` (+ тест при возможности).

Окно `useAdminDialog` рендерится внутри формы документа Payload (поле показа «Цены по схеме зала», шаблоны площадки) — вложенный `<form>` недопустим, браузер отправляет внешнюю форму. Исправить так, чтобы окно никогда не вкладывалось во внешнюю форму: рендерить `<dialog>` порталом в `document.body` (`createPortal`), и дополнительно не полагаться на submit внешней формы (Enter в поле ввода окна подтверждает окно, а не документ). Поведение для существующих экранов (сертификаты, возвраты, MFA) не меняется.

Готово, когда: «Применить шаблон» / «Сохранить как шаблон» в форме показа больше не отправляют форму показа (проверка рассуждением по коду + тест, если в проекте есть способ рендерить компоненты; иначе — описать в отчёте, почему вложенности больше нет).

### Task 2: Дата и время показа — русский формат и ручной ввод

**Files:** `src/payload/collections/Performances.ts` (поля `startsAt`, `salesStartAt`, `salesEndAt`), при необходимости `src/payload.config.ts`.

Задать полям дат `admin.date.displayFormat: 'dd.MM.yyyy HH:mm'`, 24-часовое время (`timeFormat: 'HH:mm'`, `timeIntervals: 15`), чтобы ручной ввод «15.03.2027 19:00» принимался, а календарь показывал 24-часовое время. Проверить по исходникам `@payloadcms/ui` DatePicker, что `displayFormat` используется и для разбора ввода. Описание поля «Начало» оставить про часовой пояс.

### Task 3: Удаление показа и спектакля — по продажам, с понятной ошибкой

**Files:** `src/payload/hooks/inventorySync.ts`, `src/payload/collections/Performances.ts`, `src/payload/collections/Shows.ts`, при необходимости `src/modules/inventory/*`; тесты `tests/unit/cms-inventory-sync.test.ts`.

- Показ можно удалить, если по нему нет проданных и забронированных мест/билетов (inventory: места `held`/`sold`, у категорий `sold + held > 0`) и нет позиций заказов. Иначе — отказ с текстом «Показ с проданными или забронированными билетами нельзя удалить — снимите его с публикации.» После успешного удаления — убрать inventory показа (свободные/закрытые места, категории без продаж) в той же транзакции.
- Спектакль с показами удалить нельзя: «У спектакля есть показы (N) — сначала удалите их или перенесите на другой спектакль.»
- Тексты отказов должны доходить до админки (не «An unknown error occurred»): выяснить по исходникам Payload, какой тип ошибки в `beforeDelete` показывается пользователю при удалении из админки (одиночное и массовое удаление), и использовать его.

### Task 4: Понятное название показа

**Files:** `src/payload/collections/Performances.ts`, новая миграция, тесты.

Добавить поле `title` (text, только чтение в админке, в списках и при выборе — `useAsTitle: 'title'`): «<Название спектакля> · <д месяц> <ЧЧ:ММ> · <Площадка>», дата и время — в поясе театра, по-русски («15 марта 19:00»). Заполнять хуком `beforeChange` при каждом сохранении (спектакль/площадка — по id через `req.payload.findByID`, `draft: true`, `overrideAccess: true`). Миграция добавляет колонку (и в таблицу версий) и заполняет `title` у существующих показов SQL-запросом с JOIN на `shows`/`venues` (время — `AT TIME ZONE 'Asia/Yekaterinburg'`, месяц — по-русски через CASE). `defaultColumns` показа: `['title', 'startsAt', 'venue', '_status']`. Чистая функция форматирования — с unit-тестом.

### Task 6: Категории билетов — внутри показа

**Files:** `src/payload/collections/Performances.ts`, `src/payload/collections/TicketTypes.ts`, при необходимости компонент.

- В показе блок «Билеты (категории)» сразу после «Схема зала и цены мест»: join `ticketTypes` с колонками «Название, Цена, Вместимость», создание прямо из показа (показ подставлен). Описание: «Нужны, только если продажа без схемы зала (входные билеты). Для залов со схемой цены задаются выше, на схеме.» Для зонной схемы (Хлебозавод) — «Зоны схемы продаются как категории автоматически.»

### Task 7: Спектакль — вкладка «Показы и продажи»

**Files:** `src/payload/collections/Shows.ts`, новый компонент `src/payload/components/shows/ShowPerformancesPanel.tsx` (+ CSS-модуль).

Заменить join-список на панель: все показы спектакля **включая черновики** (REST `/api/performances?where[show][equals]=<id>&draft=true&depth=1&sort=startsAt`), строка: дата и время (театра), площадка, статус (Черновик / Опубликован), продажи («открыты» / «откроются <дата>» / «нет цен» / «закрыты»), ссылка на показ. Одна кнопка «Добавить показ» — открывает создание показа в выдвижной панели Payload (`useDocumentDrawer({ collectionSlug: 'performances' })`, `initialData: { show: <id> }`), после сохранения список обновляется. Для несохранённого спектакля — «Сохраните спектакль, чтобы добавить показы». Пустое состояние объясняет: «Показ — это конкретная дата в конкретном зале. Зал, цены и билеты задаются в показе.»
